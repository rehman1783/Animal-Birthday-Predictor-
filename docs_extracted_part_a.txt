ABP — Milestone 1, Part A: Onboarding + Authentication
Build Documentation (UI-Only Build — for AI coding agent / developer handoff)
Scope of this document: Onboarding screen + Authentication UI (Sign Up, Sign In, Password Reset) — pixel/UI layer only.
Supabase is intentionally NOT wired up in this step. Buttons, forms, and navigation should all work using local/mock state (form validation, loading spinners triggered by a fake delay, etc.), so the UI is fully clickable and demo-able on its own. Real Supabase auth calls are a separate next step, once this UI is approved.
Mare / Breeding / Embryo Transfer / Camera & Gallery / Schema work will be delivered as a separate documentation part once those Figma screens are finalized.
Architecture: Flutter, Feature-First folder structure, built so later milestones (Mare, Dog module, multi-user, offline, notifications) slot in cleanly.

1.2 Typography
Display/Headline ("Animal BirthDay Predictor", "Welcome Back"): Serif display face, ~28–32sp, gold or white.
Section Label ("WHY ABP?", "OR CONTINUE WITH"): Small caps, letter-spaced, gold, ~11–12sp.
Feature Title ("Precision Tracking" etc.): Sans-serif, semi-bold, gold, ~16sp.
Body (descriptions, subtitles): Sans-serif regular, textSecondary, ~14sp, line-height ~1.5.
Button label: Sans-serif bold, dark navy text on gold gradient buttons.
Build these as AppTypography constants — don't inline sizes per screen.
1.3 Shape & Spacing
Card / button corner radius: ~16px (pill-style on the primary CTA).
Icon containers: ~48x48px, rounded square (~12px radius), surface background, gold icon glyph.
Screen horizontal padding: ~24px.
Section vertical spacing: ~32–40px between major blocks.

3. Feature-First Folder Structure (Flutter)
Feature-first: each feature owns its own screens/widgets/state, with only truly shared pieces (design tokens, shared widgets) living in core/. This step only needs the presentation layer per feature — domain/data folders are stubbed as empty placeholders now and filled in during the Supabase/logic step, so the structure doesn't need to be reshuffled later.

Why this ordering works: because domain/data for auth are just not created yet (rather than created empty and unused), there's nothing to rip out later — the next step adds those folders and swaps auth_form_state.dart's fake-delay logic for real repository calls, without touching how the screens are built.
4. State Management (UI-only step)
Use simple local state (StatefulWidget + setState, or a lightweight ChangeNotifier/StateNotifier scoped to each screen) to handle:
Form field values and validation errors.
An isLoading boolean toggled by a fake Future.delayed(...) when a button is tapped, so the loading spinner/disabled-button UI can be built and tested now.
Password-reset success state swap (form → confirmation view).
No app-wide auth state, no Riverpod/Bloc provider wiring to a backend yet — that architecture decision can be made in the next step once real Supabase calls are being introduced, since it affects the app more broadly than this UI-only pass does.
5. Open Items (flagged, not blockers for this UI-only step)
Password minimum-length/complexity rule — using 8 characters as a placeholder; confirm before the logic step.
Terms of Service / Privacy Policy destination pages — don't exist yet; leave as plain text/disabled link.
"Keep me signed in" toggle's real behavior — decide before wiring actual session persistence.
Whether Sign Up leads to an email-confirmation state or straight into the app — depends on Supabase project settings, decided in the next step.
