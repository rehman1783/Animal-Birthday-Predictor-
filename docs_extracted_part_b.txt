2. Database Schema (Supabase / Postgres)
One consistent design decision runs through this schema: pregnancy is tracked against whichever animal is actually carrying the foal — the donor mare herself for Natural/Chilled/Frozen breeding, or the recipient mare for an embryo transfer. See Section 3. Markings and Preventative Care are both polymorphic tables (owner_type + owner_id) so the same structure serves Mare, Recipient Mare, and Foal without three separate copies.
Revised from the first draft of this document: (1) embryo transfer is now a yes/no question available after ANY breeding method, not just ICSI — a Natural/Chilled/Frozen-bred embryo can also be flushed and transferred to a recipient, this isn't ICSI-exclusive; (2) ultrasound images are now stored per scan (scan_1/2/3) instead of one shared field, since each scan visit produces its own image.

3. Calculation Logic — Scan Dates & Foaling Due Date
Key architectural decision: pregnancy is always tracked against whoever is physically carrying the foal.
Natural / Chilled / Frozen without embryo transfer: the donor mare carries her own foal → pregnancy_records.carrier_type = 'mare', dates calculated from breeding_records.cover_or_transfer_date.
Any method WITH embryo transfer (including ICSI, which is transferred by nature of the procedure): a recipient mare carries the foal → pregnancy_records.carrier_type = 'recipient_mare', dates calculated from recipient_mares.transfer_date.

Breeding Path | Carrier | Scan 1 | Scan 2 | Scan 3 | Foaling Due
Natural (no transfer) | Donor mare | cover date + 14 days | + 30 days | + 45 days | cover date + 341 days
Chilled (no transfer) | Donor mare | cover date + 14 days | + 30 days | + 45 days | cover date + 341 days
Frozen (no transfer) | Donor mare | cover date + 14 days | + 30 days | + 45 days | cover date + 340 days
Any method + Embryo Transfer, or ICSI | Recipient mare | transfer date + 7 days | + 30 days | + 45 days | transfer date + 332 days

Build this as one pure function — calculatePregnancyDates(carrierType, baseDate) → {scan1, scan2, scan3, foalingDue} — called once when a breeding_records or recipient_mares row is saved, writing the results into pregnancy_records. Don't recalculate on every screen load: store the computed values so a vet-adjusted scan date isn't silently overwritten later.
Frozen's foaling due date (340 days) is intentionally 1 day less than Natural/Chilled's (341) despite identical scan offsets — keep this exactly as specified, it's not a typo.

4.3 Breeding Details
"How was your mare bred" — Natural / Chilled / Frozen / ICSI (single-select).
"Was the resulting embryo transferred to a recipient mare?" — Yes/No, shown after any method is selected (not ICSI-only, see Section 2's revision note).
Date of cover/insemination (if known).
Photo (e.g. of the insemination straws).
Layout: the 4 method options as a single-select row of pill/chip buttons (not plain checkboxes) so only one can be active at a time, matching the gold-accent selected state used elsewhere in the app; the transfer Yes/No question appears directly beneath once a method is chosen.
Data flow — Save: insert breeding_records; if "transferred" = Yes, navigate to Recipient Mare Details (4.6) next, and hold off creating pregnancy_records until that recipient record exists. If "transferred" = No, immediately run Section 3's calculation with carrier_type='mare' and insert pregnancy_records. Load: read back the saved method/date/photo for editing.
4.4 Pregnancy Details
1st / 2nd / 3rd Preg Scan due on — system-calculated, shown read-only, each with its own "Pregnancy Confirmed" checkbox and its own scan photo upload.
Static warning banner: "Early Pregnancy Scan Day 14-16 post cover/insemination. To reduce the risk of multiple pregnancies, it is strongly recommended to have your mare scanned by your veterinarian. Multiple pregnancies are dangerous and early detection is your best chance to safely manage them."
Vet Name / Vet Mobile — user input, with a "Save Vet Details" action; shows a "No Vet Added" state until saved, and a call-vet shortcut once it is.
Layout: the 3 scans as three matching sub-cards in a vertical sequence (due date + confirmed toggle + photo slot each), so the pattern is visually obvious as "scan 1, then 2, then 3" rather than three unrelated fields.
Data flow — Save: update the relevant scan_N_confirmed / scan_N_image_url / vet_name / vet_mobile columns on the existing pregnancy_records row (the due dates themselves were already written when the record was created in 4.3/4.6). Saving any scan date here also writes a matching row into calendar_reminders. Load: read the single pregnancy_records row for this carrier and populate all three scan blocks plus vet info.

4.7 Preventative Care — Mare
Vaccinations section — one row per vaccine, each a date field + done checkbox: Tetanus, Strangles, Equine Herpes Virus, Rotavirus, Hendra (AUS), EQ Influenza (EU & UK), EEE/WEE/WNV (USA), Rabies (USA), plus Wormer.
These are user-entered dates, not auto-calculated (per the client's own conclusion that the full priming logic is too variable to hard-code). Show the client's reference intervals as small helper text under each field for guidance only.
Dentistry & Farrier section — Dental (date + done), Dentist No. (phone, with Save + a "No Dentist Number Added" empty state + a Call action), and the same pattern for Farrier.
Layout: split into the two clearly labeled sections above (a SectionDividerLabel each), each vaccine as its own compact row rather than the old app's single unbroken checklist — this was the densest screen in the old app and is worth the most visual cleanup.
Data flow — Save: update the corresponding column(s) on the single preventative_care row for this mare (owner_type='mare', owner_id=<mare id>; create the row on first save if it doesn't exist). Every date saved here also writes a calendar_reminders row. Load: fetch that one row and populate every field; unset vaccines simply show their date picker empty.

4.9 Foal Preventative Care
Same field set and layout pattern as 4.7 (Tetanus, Strangles, EQ Herpes, Rotavirus, Hendra, EQ Influenza, EEE/WEE/WNV, Rabies), stored in the same preventative_care table with owner_type='foal', owner_id=<foal id>.
Static disclaimer: "All foals require a priming vaccination program for most vaccinations, always consult your Veterinarian for correct schedule and vaccine for your region. Please note the Vaccination Status of the pregnant mare will affect the start date of the priming program."
Worth building as a real UI cue, not just static text: when this screen loads, also fetch the dam mare's own preventative_care row and show a small note like "Mare's Tetanus recorded [date]" next to the matching foal field, so the relationship the disclaimer describes is actually visible.
Data flow: identical pattern to 4.7, just scoped to the foal's own row plus a read-only lookup of the dam's record for the reference note above.
